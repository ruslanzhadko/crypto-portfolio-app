# Уведомления по позициям — план (23.10.2026, не начато)

Новый тип алертов рядом с ценовыми триггерами монет: события биржевых позиций. Канал тот же —
Telegram и журнал на сайте (красная точка у «Алертов»).

## 1. Виды

| Вид | Срабатывает | Параметр | Повтор |
| --- | --- | --- | --- |
| Позиция открыта | на счёте появилась новая позиция | счёт или все счета | каждое открытие |
| Позиция закрыта | позиция исчезла; в тексте закрытый PnL (точный, где биржа его отдаёт, иначе «≈» по последнему uPnL) | счёт или все | каждое закрытие |
| Размер изменился | доливка или частичное закрытие больше N% | позиция, N% | каждое изменение |
| Ликвидация близко | до цены ликвидации осталось меньше N% | позиция или все, N% (по умолчанию 10%) | снова после отхода на N+3% |
| PnL | uPnL пересёк $X или ROE ±Y% от маржи | позиция | один раз до возврата на 10% от порога |
| Безубыток (BU) | mark-цена вернулась к цене безубыточности | позиция | одноразовый |
| Фандинг: ставка | следующая ставка против стороны позиции больше N% | позиция или монета | раз за период фандинга |
| Фандинг: платёж | ожидаемый платёж (размер × ставка) больше $X | позиция | раз за период |
| Фандинг: накоплено | уплачено за позицию больше $X или Y% маржи | позиция | один раз |

Безубыток, PnL, фандинг и ставка не считаются там, где данных нет (см. EXCHANGES.md: Aster без
API Wallet, POINT-комиссии Gate): кнопка создания не показывается, «0» не подставляется.

## 2. Интерфейс

- **Алерты:** вкладки «Монеты · Позиции · Лог». В создании первый шаг — тип: «Монета» (как сейчас)
  или «Позиция» (список видов из §1). Для позиции выбирается конкретная позиция из открытых или
  «любая позиция» на счёте или на всех счетах (для открытия, закрытия, ликвидации).
- **Страница позиций, раскрытая карточка:** маленькая иконка-колокольчик рядом с полем:
  фандинг → «платёж больше $X / ставка больше N%», PnL → «PnL достигнет $X / ROE Y%», BU → «вернуться
  к безубытку» (одно нажатие), ликвидация → «ближе N%». Открывается компактная панель (на телефоне —
  снизу) с готовым значением по умолчанию, одна кнопка «Создать». Иконка закрашена, если алерт по
  этому полю уже есть; повторное нажатие — изменить или выключить.
- На карточке позиции значок колокольчика с числом активных алертов.
- Алерты конкретной позиции после её закрытия архивируются сами (видны в журнале, не в списке).
- Быстрые переключатели в настройках: «сообщать об открытии и закрытии позиций» и «ликвидация
  ближе 10%» для всех счетов — без создания правил вручную.

## 3. Как считать (с учётом бюджета Neon)

- Считает **exchange worker на VM**: у него ключи и позиции. Правила читаются из БД в окне :00/:30 и
  в течение минуты после правки (тот же сигнал через Runtime Cache, что у ценовых триггеров).
- Если у пользователя есть активные алерты по позициям, worker держит для него лёгкий режим
  наблюдения: только позиции с биржи раз в 30–60 с, **в памяти, без БД**. В БД пишется только
  срабатывание (журнал + сигнал на сайт). Без алертов — как сейчас (окно раз в 30 минут).
- Открытие и закрытие — сравнение набора позиций с предыдущим опросом в памяти; после перезапуска
  базой служит последнее состояние из БД, чтобы не прислать ложные «открыта».
- Защита от спама: повтор только после возврата за порог с запасом (см. «Повтор»), не чаще раза в
  5 минут на правило, несколько событий за опрос — одним сообщением.

## 4. Данные (миграция только добавляет)

- Таблица `PositionAlert`: `userId`, `kind`, область (`connectionId?`, `accountId?`, `symbol?`, `side?`,
  `positionKey?`), `params` JSON (порог и единица), `isActive`, `oneShot`, `lastFiredAt`, `archivedAt`.
- `NotificationLog`: новые nullable `positionAlertId`, `kind` — журнал и красная точка общие.

## 5. Этапы

1. Открытие и закрытие позиций и «ликвидация близко» (переключатели в настройках, режим наблюдения
   в worker, журнал).
2. Кнопки на странице позиций: BU, PnL, ликвидация для конкретной позиции.
3. Фандинг: ставка, платёж, накоплено.
4. Размер позиции, вкладка «Позиции» в алертах с полным редактором.

## 6. Открытые вопросы владельцу

1. Открытие и закрытие — включены по умолчанию для всех пользователей с биржами или по желанию?
2. Режим наблюдения раз в 30–60 с при активных алертах — подходит, или только пока сайт открыт?
3. Закрытый PnL там, где биржа его не отдаёт, — показывать «≈» по последнему uPnL или не показывать?
4. Фандинг: порог в долларах за платёж, в процентах ставки или оба варианта?
