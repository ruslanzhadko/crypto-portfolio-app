# Уведомления по позициям — план (решения владельца 25.10.2026)

Новый тип алертов рядом с ценовыми триггерами монет: события биржевых позиций. Канал тот же —
Telegram и журнал на сайте (красная точка у «Алертов»).

## 1. Виды

| Вид | Срабатывает | Параметр | Повтор |
| --- | --- | --- | --- |
| Позиция открыта | на счёте появилась новая позиция | счёт или все счета | каждое открытие |
| Позиция закрыта | позиция исчезла; в тексте закрытый PnL (§3a) | счёт или все | каждое закрытие |
| Размер изменился | доливка или частичное закрытие больше N% | позиция, N% | каждое изменение |
| Плюс / минус | uPnL перешёл через ноль (позиция ушла в плюс или в минус) | позиция или все | после отхода от нуля на 0,5% от маржи |
| Безубыток (BU) | mark-цена вернулась к цене безубыточности | позиция или все | одноразовый на позицию |
| Профит / убыток | uPnL пересёк $X или ROE ±Y% от маржи | позиция | один раз до возврата на 10% от порога |
| Ликвидация близко | до цены ликвидации осталось меньше N% | позиция или все, N% (по умолчанию 10%) | снова после отхода на N+3% |
| Фандинг: ставка | следующая ставка против стороны позиции больше N% | позиция или монета, **порог в %** | раз за период фандинга |
| Фандинг: платёж | ожидаемый платёж (размер × ставка) больше N% маржи позиции | позиция, **порог в %** | раз за период |
| Фандинг: накоплено | уплачено за позицию больше N% маржи | позиция, **порог в %** | один раз |

Пороги фандинга — только в процентах (решение 25.10). Безубыток, PnL и фандинг не считаются там,
где данных нет (Aster без API Wallet, POINT-комиссии Gate — EXCHANGES.md): переключатель показан
с пометкой «недоступно для этого счёта», «0» не подставляется.

## 2. Интерфейс

- **Настройки → «Уведомления» (главное, решение 25.10):** отдельная карточка со всеми видами из §1,
  у каждого переключатель вкл/выкл и порог по умолчанию (например, ликвидация 10%, фандинг 0,1%).
  Действует на все позиции всех счетов; при желании — исключить отдельные счета. Там же общий
  выключатель Telegram (сейчас `telegramNotificationsEnabled`) и ценовые триггеры монет.
- **Алерты:** вкладки «Монеты · Позиции · Лог». Во вкладке «Позиции» — правила для конкретной позиции
  (переопределяют настройки по умолчанию).
- **Страница позиций, раскрытая карточка:** колокольчик рядом с полем (фандинг, PnL, BU, ликвидация)
  открывает компактную панель (на телефоне — снизу) с готовым значением и кнопкой «Создать».
  Закрашен, если правило уже есть; повторное нажатие — изменить или выключить. На карточке —
  число активных правил.
- Правила конкретной позиции после её закрытия архивируются сами (видны в журнале, не в списке).

## 3. Как считать (с учётом бюджета Neon)

- Считает **exchange worker на VM**: у него ключи и позиции. Правила и настройки читаются из БД в окне
  :00/:30 и в течение минуты после правки (сигнал через Runtime Cache, как у ценовых триггеров).
- **Фоновый опрос (решение 25.10):** если у пользователя включён хоть один вид, worker опрашивает его
  позиции с биржи всегда, а не только пока открыт сайт: цель — раз в **15 с**, не реже раза в
  **30 с**. Только в памяти, без БД; в БД пишется только срабатывание (журнал + сигнал сайту).
- Предел частоты задают не Neon, а лимиты бирж на один IP VM (все пользователи идут с одного IP).
  Перед выпуском замерить вес запросов на подключение и посчитать бюджет: например, Binance
  `positionRisk` — малая доля минутного лимита IP, т. е. десятки подключений раз в 15 с помещаются.
  Интервал подстраивается сам: при ответе 429/418 или приближении к лимиту (заголовки веса) —
  замедление до 30–60 с для этой биржи, с записью в лог.
- Открытие и закрытие — сравнение набора позиций с предыдущим опросом в памяти; после перезапуска
  базой служит последнее состояние из БД, чтобы не прислать ложные «открыта».
- Защита от спама: повтор только после возврата за порог с запасом (см. «Повтор»), не чаще раза в
  5 минут на правило, несколько событий за опрос — одним сообщением.

### 3a. Закрытый PnL (решение 25.10: всегда что-то показывать)

Точный — из истории биржи сразу после закрытия: Binance `income` (REALIZED_PNL), Bybit `closed-pnl`,
OKX `positions-history`, Gate `position_close`, Hyperliquid `userFills` (`closedPnl`), Aster с API Wallet
`userTrades`. Где точного нет, показывается «≈ $X» по последнему uPnL из опроса:

- Aster без API Wallet (публичный кошелёк — истории сделок нет);
- Gate с комиссиями в POINT (итог не подтверждается);
- история биржи не ответила или ещё не появилась за ~1 минуту после закрытия;
- позицию закрыли или ликвидировали между опросами — тогда «≈» по последнему опросу, с пометкой.

## 4. Данные (миграция только добавляет)

- `NotificationSettings` (или JSON-поле у `User`): вид → вкл/выкл, порог, исключённые счета.
- `PositionAlert`: `userId`, `kind`, область (`connectionId?`, `accountId?`, `symbol?`, `side?`,
  `positionKey?`), `params` JSON (порог), `isActive`, `oneShot`, `lastFiredAt`, `archivedAt`.
- `NotificationLog`: новые nullable `positionAlertId`, `kind` — журнал и красная точка общие.

## 5. Этапы

1. Карточка «Уведомления» в настройках, фоновый опрос в worker с замером лимитов, открытие/закрытие
   (с PnL по §3a), ликвидация близко, плюс/минус. **Код готов 27.10** (`lib/positions/`, карточка в настройках,
   опрос в `scripts/exchange-worker.ts`); закрытый PnL пока только «≈» по последнему опросу — точный из истории
   бирж (§3a) следующим шагом; лимиты адаптивные (429 → 60 с на 5 минут), замер веса на живых ключах — после
   выпуска. Выпущено в `main` 27.10.
2. Безубыток, профит/убыток; колокольчики на странице позиций.
3. Фандинг: ставка, платёж, накоплено (пороги в %).
4. Размер позиции, вкладка «Позиции» в алертах с полным редактором.
