# Позиции в боте и Telegram Mini App

`/positions` в боте (§1–2) выпущен 31.10. Мини-апп (§3–5) — план, стартует только
после решения владельца по правилам Telegram (§4).

## 1. Решение: снимок по запросу, без автообновления

- Команда `/positions` (и пункт меню) присылает **снимок** позиций с кнопкой «🔄 Обновить».
- Сообщение **не обновляется само**: Bot API не сообщает, смотрит ли человек в чат, поэтому правки уходили бы
  вслепую — и для каждого открытого сообщения шёл бы опрос бирж. Живое обновление — задача мини-аппа (§3).
- Старые сообщения не трогаем и их id не храним. Кнопка под старым сообщением обновляет только его.

Пример (лимит Telegram — 4096 символов; сортировка по размеру, до 20 позиций, дальше «…и ещё N»):

```text
📈 Позиции · 3 · uPnL +128,40 $
Данные на 14:32:05

🟢 BTC лонг 10x · Binance
+96,20 $ (+12,4%) · размер 7 800 $
вход 94 210 · цена 95 370 · до ликв. 8,7%
```

## 2. Откуда берутся свежие данные

Проблема: в простое `ExchangePosition` в БД обновляется раз в 30 минут (INFRASTRUCTURE §3.1), а опрос
уведомлений раз в 15 с живёт только в памяти worker. Простое чтение БД может показать позицию получасовой давности.

Режим «пользователь смотрит» (`markExchangeActivity`) для бота не подходит: одно нажатие включает запись в БД каждые
~30 с на 10 минут, хотя человек мог закрыть чат сразу.

Поэтому **разовый запрос**, по образцу существующего сигнала через Runtime Cache:

```text
/positions → webhook (Vercel) → снимок из БД с временем данных → sendMessage
                 │ снимок старше 60 с
                 ▼
         Runtime Cache: { userId, chatId, messageId }
                 ▼ (worker и так читает /api/worker/activity раз в 10 с)
         worker: память опроса уведомлений, если ей меньше 15 с, иначе один adapter.fetch(false)
                 ▼
         одна правка этого сообщения; в БД ничего не пишется
```

- Ответ мгновенный, свежие цифры — в среднем через 5–15 с, затем правок нет.
- Дополнительного постоянного опроса нет: запрос бота дополняет ответ уже работающего сигнала.
- Если сигнал потерялся, сообщение остаётся со старым временем и кнопкой — это честно и безопасно.
- «Обновить»: не чаще раза в 15 с на чат; при повторе — всплывающий ответ, без запросов к БД и биржам.
- Лимиты Telegram не ограничивают: около 1 сообщения в секунду на чат и 30 в секунду всего, а правка здесь одна.

Кнопка «Обновить» всегда идёт через worker и не читает позиции из БД на Vercel: так свежие цифры в сообщении не
заменяются более старыми из базы. Если worker не в сети, кнопка перерисовывает сообщение из БД, с временем данных.

Код: `lib/telegram/positions-bot.ts` (формат, снимок из БД), `lib/positions/view-requests.ts` (запросы в Runtime Cache),
`lib/positions/view-refresh.ts` и `PositionAlertService.readForView` (чтение и правка на worker),
`app/api/telegram/webhook/route.ts`.

После выпуска: один раз переустановить webhook — `setMyCommands` вызывается только в `setWebhook`, без этого
`/positions` работает, но не появится в меню.

## 3. Mini App: что это и что нужно

Мини-апп — обычный сайт, который Telegram открывает во встроенном WebView (в web-версии Telegram — в iframe) и передаёт
ему подписанные данные пользователя. Это **тот же проект и тот же домен**: отдельный код не нужен, переписывать сайт тоже.
Мобильная вёрстка и `mobile-nav` уже есть. Главное отличие от бота: `isActive` и события `activated` / `deactivated`
(Bot API 8.0+) показывают, смотрит ли человек, поэтому автообновление можно останавливать, когда приложение свёрнуто.

Запуск: Main Mini App и кнопка меню настраиваются в BotFather; кнопка `web_app` под сообщением; ссылка
`t.me/<бот>?startapp`.

| Часть | Что сделать |
| --- | --- |
| Вход | Страница `/tma`, клиентский компонент передаёт `initData`; новый Auth.js-провайдер проверяет на сервере подпись (HMAC от токена бота) и `auth_date` (не старше 5 минут), находит пользователя через `lib/auth/telegram-identity.ts` и выдаёт обычную сессию. `initDataUnsafe` не используется. Остальные страницы и API не меняются |
| Cookie | В WebView телефона сайт открыт напрямую. В web.telegram.org он в чужом iframe, а сессия Auth.js сейчас `SameSite=Lax`, и cookie может не отправляться. Проверить на прототипе; запасной вариант — открывать там сайт в обычной вкладке, чтобы не ослаблять cookie для всех |
| Заголовки | Сейчас `X-Frame-Options` и CSP нет, встраивание не заблокировано. Ничего не добавлять такого, что запретит `web.telegram.org` |
| Оболочка | Скрипт `telegram-web-app.js` — только в режиме мини-аппа; `ready`, `expand`, `BackButton` ↔ роутер, `contentSafeAreaInset` в CSS, `viewportStableHeight` вместо `100vh`, `disableVerticalSwipes`, цвет шапки, язык из `language_code` |
| Ссылки | Внешние — только через `openLink` (с Bot API 10.2 методы мини-аппа работают лишь на её исходном домене; наш домен один, поэтому это не мешает) |
| Обновление | Существующий опрос 15 с и отметка активности — только пока `isActive`; при `deactivated` пауза. Нагрузка не больше, чем у открытой вкладки сайта |
| Границы v1 | Только просмотр. Ввод API-ключей, смена пароля, удаление аккаунта — на сайте |

Порядок: прототип на **отдельном тестовом боте** → вход → оболочка → проверка на iOS, Android, Desktop, Web → кнопка
в основном боте. В боте «Открыть на сайте» заменяется кнопкой `web_app`; `/positions` остаётся быстрым снимком.

## 4. Риск: правила Telegram для крипто-приложений — решение владельца

[Условия для разработчиков](https://telegram.org/tos/bot-developers), §7, и
[Blockchain Guidelines](https://core.telegram.org/bots/blockchain-guidelines):

- мини-аппы с криптофункциями, в том числе «в связанном боте», должны быть основаны только на TON;
- нельзя продвигать активы и кошельки вне TON и вести пользователя на внешние площадки, где такие активы продвигаются
  или используются;
- цифровые товары и услуги внутри — только за Telegram Stars (§6.2).

Режим только для просмотра и трекеры портфеля в этих текстах **не упомянуты**: ни разрешения, ни прямого запрета нет.
Но под формулировки могут подойти Binance/Hyperliquid/EVM-кошельки, ссылки «открыть на бирже» и криптолента.
Это чтение правил, а не юридическое заключение. Худший случай — санкции к боту, через который идут уведомления.

Рекомендация:

1. Прототип — только для владельца и пилота, на отдельном боте, без публикации и рекламы.
2. В режиме мини-аппа убрать ссылки на биржи и токены и не показывать криптоленту.
3. Перед публичным запуском запросить разъяснение Telegram; основной бот подключать к мини-аппу только после ответа.
4. Платные функции, если появятся: в мини-аппе — Stars.

`/positions` в боте от этого решения не зависит: мини-апп там не появляется.
